# 棱镜设计与数据流

适用版本：0.2.2。本文描述已实现的结构；日常操作见 [使用指南](使用指南.md)。

## 职责

棱镜独立记录主观情绪与经历，向接入方提供读取接口。它不承担共同现实、承诺调度或角色回复发送。与光谱协作时，光谱使用这些信息作为背景，并继续负责共同生活与行为状态。棱镜是可选组件，两者分别保存各自数据。

## 两条处理路径

当前互动路径：消息 → 人物与会话识别 → 模型理解当前互动 → 人格与情绪评估 → 心情和人物感受更新 → 状态读取接口。

经历整理路径：往来积累 → 场景边界判断 → 场景封存 → 可选的主观叙事生成 → 场景、痕迹与联想图保存 → 话题相关回忆召回。

前一条用于及时更新背景情绪，后一条通过批量和安静整理条件保持经历连续。是否生成文字由配置控制；模型调用次数受实际往来和整理条件影响。

## 主要模块

| 职责 | 模块 |
|---|---|
| 当前互动理解与批量阅读 | `reading_model`、`reading`、`batch` |
| 人格、情绪与人物感受 | `personality`、`appraisal`、`affect`、`interperson` |
| 场景边界与经历文字 | `boundary`、`open_scene`、`scene`、`scene_writer` |
| 联想、淡化与召回 | `assoc`、`decay`、`recall` |
| 状态快照与信息范围 | `state`、`visibility`、`resolve` |
| 持久化与面板 | `store`、`page_api` |
| 配置与运行协调 | `settings`、`runtime`、`provider_pick` |

插件入口协调框架事件、模型调用、保存和公开读取，不要求光谱直接读取棱镜数据库。保存场景、痕迹与联想图采用事务，避免一批数据只保存一部分。

## 数据与边界

`prism.db` 保存经历、记忆痕迹和联想结构。场景叙事代表角色的主观版本，允许淡化、概括与再巩固。人物标识与可见范围用于约束当前召回；主观回忆不提升为共同现实或行动指令。

这些机制是工程上的角色模拟，不表示心理学模型已证明能够复现真实人的心智。表达效果需要结合具体人设与所用模型观察。
